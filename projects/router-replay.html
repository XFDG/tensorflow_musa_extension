Projects/MoE Router Replay
Flagship Project · RL Infra

MoE Router Replay：建立训推路由一致性的正确性—性能—效果闭环。

在 MoE 模型的 RL Post-training 链路中，rollout 与 training 可能因为执行路径、数值精度或实现差异选择不同 experts。这个项目不只验证 R3 Replay 是否让路由一致，还同时评估概率漂移、CUDA Graph、系统性能和训练稳定性。

RoleExperiment & Infra Engineering
Environment8× NVIDIA H200 · TP=2
StackveRL · Megatron · vLLM
Status脱敏案例 · 持续整理
01 / Problem

问题不是“能不能 Replay”，而是“Replay 的路径是否真的与采样一致”。

在 rollout 阶段，MoE Router 会为每个 token、每一层选择 top-k experts；训练阶段需要重新前向并计算 logprob、KL 和梯度。如果两侧 router 的 top-k 结果不同，训练使用的 token—expert 路径就偏离了采样时真实发生的路径，可能污染概率对齐与策略更新。

造成差异的来源可能同时存在：浮点数值误差、不同算子实现、执行顺序、CUDA Graph / compiled path、mask 处理、token 索引对齐或 replay 数据的通信与布局。

核心任务

搭建 Baseline、R2 Record 与 R3 Replay 的可比实验，并将“路由是否一致”“概率是否更接近”“系统是否更快”“训练是否稳定”拆成独立但关联的指标层。

Rollout 侧采集 routed experts，训练侧按照 response mask 对指定 token/layer 进行 replay。为了避免“统计看起来一致但索引错位”，必须同时记录有效 token-layer 数量，并让 overlap/mismatch 的分母与 mask 语义一致。

03 / Hypotheses

四个可被证伪的假设

  1. H1 · 正确性：开启 R3 Replay 后，被 replay 的有效 token/layer 上 route_mismatch_rate 应接近 0，topk_overlap 应接近 1。
  2. H2 · 概率对齐：R3 相比 Baseline / R2 应显著降低 logprob drift；R2 只记录不重放，不应自动改善 drift。
  3. H3 · 性能：Replay 不应引入不可接受的记录、通信、拷贝或训练侧执行开销；CUDA Graph 的收益与限制需要单独消融。
  4. H4 · 训练效果：短程正确性成立后，长程 reward、KL、clipfrac 与 grad norm 至少不能明显退化。

06 / Debugging

最重要的失败路径：CUDA Graph / compiled sampler 超时。

在预验证阶段，采样路径出现 sample_tokens timeout。直接把问题归因于 Router Replay 会混淆变量，因此先切到 eager 模式，确认 Baseline / R2 / R3 在相同条件下能够稳定完成，再回到 CUDA Graph 路径定位 capture、动态输入与 sampler 实现的交互。

Observed:
  compiled sampler / CUDA Graph path → sample_tokens timeout

Isolation:
  force eager execution
  keep model, data, TP, sampling and metrics unchanged

Result:
  baseline / R2 / R3 → 0 hang, metric_error = 0

Engineering decision:
  correctness first; re-enable graph only after replay path is verified

08 / Next

下一步验证

  1. 补齐 R2 / R3 的长程 reward、KL、grad norm 与 validation 对照，确认概率对齐能否转化为训练收益。
  2. 拆分 Record、Transport、Replay 与 Metric 的时间成本，建立 per-token / per-stage 性能账本。
  3. 重新开启 CUDA Graph，最小化 capture 变量并确认 sampler timeout 根因。
  4. 扩展到不同 MoE 模型、top-k、并行配置和硬件环境，验证结论的可迁移性。
