02 / Case Study A

GELU Fusion：从“支持算子”走到“整网真正融合”。

工作不只是增加一个 muDNN GELU 调用，而是补齐图融合链路和 benchmark，定位大图场景下部分 GELU 未命中 Fusion Pattern 的原因，并验证真实 shape。

  3. 使用真实 shape 建立 correctness + latency benchmark，验证融合后的实际收益。
03 / Case Study B

长跑 OOM / 随机崩溃：根因是 HostMemory 语义，而不是显存“不够”。

整网推理长跑出现 OOM 和随机退出。通过逐层缩小范围，发现 shape tensor 在 StridedSlice<int32> / Pack<int32> 等链路中错误进入 device path，导致生命周期与访问路径异常。

Symptom:
  long-run inference → OOM / random crash

Root cause:
  shape tensor with host semantics
  incorrectly placed on device path

Fix direction:
  rebuild HostMemory configuration
  align scalar / shape inputs with TensorFlow op semantics
  add use_locking=True validation for gradient ops
≈30%修复前 500 轮成功率BEFORE
100%修复后 1000 轮验证AFTER
40K / 400K / 800K进一步长跑验证轮次STABILITY

05 / Hot Path

Logical_Or scalar broadcast 热点优化

通过识别 scalar broadcast 的特定路径，减少通用实现带来的额外开销，同时补齐 Logical_And 相关测试，保证优化不破坏算子语义。

21.2 μs优化前平均耗时BASELINE
10.7 μs优化后平均耗时OPTIMIZED
8187.48 → 8284.65脱敏整网吞吐变化E2E

同时参与 AddV2 热点路径、ResourceApplyAdam / ApplyGradientDescent 等训练算子的语义与结果对齐。这些工作共同强化了一个认识：微型算子 latency 只有映射到调用频次和整网占比后，才有真实优化价值。
